# NEXPOS Early Access: System Parameters & Current Capabilities

To ensure full transparency and a successful partnership, please review the current parameters of the NEXPOS Early Access build. We believe in setting clear expectations so you know exactly what the system can do today, and what is coming tomorrow.

### 1. Beta Environment & Demo Data
- **Current State:** The current demonstration link runs in a beta environment pre-loaded with synthetic demo data (e.g., sample shoes, sample customers) to illustrate workflows.
- **What this means:** When you deploy your pilot, you will start with a clean database tailored exclusively to your actual inventory.

### 2. Cash-Only Checkout Processing
- **Current State:** The V1 POS terminal successfully processes and records cash transactions end-to-end.
- **What this means:** Direct API integrations for automated Mobile Money prompts or Card Terminal links are not active in this release. Cashiers will currently process mobile money on their separate devices and record the final transaction in NEXPOS as a completed sale.

### 3. Placeholder Expansion Modules
- **Current State:** On the system sidebar, you will see modules such as *Transfers, Expenses, Purchases, Suppliers,* and *Control Center*.
- **What this means:** These are architectural placeholders for our upcoming expansion modules. Clicking them currently displays a "Coming Soon" notice. They are visible to demonstrate the comprehensive roadmap we are actively building upon the current stable core.

### 4. Foundational Reporting
- **Current State:** The reporting dashboard provides reliable, high-level aggregates of daily sales and inventory metrics.
- **What this means:** Highly granular, customizable reports (e.g., specific profit-margin-by-variant over a custom 3-year date range) are planned for a future update.

### 5. Web-Based Architecture
- **Current State:** NEXPOS is a progressive web application optimized for desktop and tablet browsers.
- **What this means:** There is no standalone downloadable mobile app in the Google Play or Apple App Store at this time. It is best experienced on a tablet or desktop computer at the checkout counter.

### 6. Connectivity
- **Current State:** The system requires an internet connection for real-time cloud synchronization across branches.
- **What this means:** While the architecture is designed to support future offline-first capabilities, a stable internet connection (WiFi or 4G) is highly recommended for the Early Access pilot to ensure immediate data accuracy across your business.
